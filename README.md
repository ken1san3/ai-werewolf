# AI Werewolf

ローカルLLMで動く9体のAIエージェントが、**サーバ権威のゲームサーバ**にWebSocketで接続し、
リアルタイムの自由会話で議論・推理・騙り・投票・夜の能力使用を行う人狼ゲーム基盤です。

「LLMに人狼のロールプレイをさせる」のではなく、**ルールと秘密情報をサーバが管理し、
AIは他のクライアントと同じプロトコルだけで参加する**構成にしています。
AIが間違えてもゲームのルールは壊れず、AIに渡る情報もネットワーク配送の段階で制限されます。

> 個人開発プロジェクトです（2026-08-29〜、452 commits）。ルールは人狼ジャッジメント（そらいろ株式会社）の
> 公式ヘルプを参照していますが、非公式であり同社とは関係ありません。

## 1. 何を作ったか

| 部分 | 内容 |
|---|---|
| ゲームコア `server/aiwolf_core/` | フェーズ進行・投票・夜行動の解決・死亡・勝敗判定・イベント記録。LLMに依存せず単体でテスト可能 |
| ネットワークサーバ `server/network/` | WebSocketセッション、認証付き着席・再接続、公開/非公開イベントの配送、行動要求の検証 |
| プロトコル `protocol/` | JSON Schemaで定義したバージョン付きメッセージ（v1 → v1.1 → v1.2） |
| 役職・ルールデータ `content/` | 13役職・陣営・能力・効果・チャットチャンネル・プリセットをYAMLで定義 |
| AIエージェント `ai_agent/` | プロトコルだけでサーバに接続する9体のAI。発言判断・発話生成・反復抑止・記録 |
| 評価・実験基盤 `ai_agent/` | 会話品質と秘密漏洩の機械チェック、複数ローカルモデルの長時間比較、感想戦、リプレイ |

## 2. なぜ作ったか

人狼は「各プレイヤーが知ってよい情報が違う」「嘘が許される」「順番の決まっていない会話で
他人の発言に反応する」ゲームです。LLMエージェントの

- 秘密情報の扱い（知らないはずのことを話さない、他人の秘密を受け取らない）
- 会話の成立（質問に答える、反論する、意見を変える、同じことを繰り返さない）
- 戦略的な嘘と、事実の取り違えの区別

を、**実際に動くシステムの中で測れる題材**として選びました。
将来は人間の参加・複数PCからの接続・異なるLLM同士の対戦・役職の追加（MOD）まで拡張できる基盤を目標にしています。

## 3. 技術的に難しいところ

- **秘密情報の境界**: 役職・夜の結果・人狼同士の会話は、そのプレイヤーにしか送れません。
  プロンプトで「言わないで」と頼むのではなく、そもそもサーバが送らない設計にしています。
- **信用できないクライアント**: AIは存在しないプレイヤーへの投票や、使えない能力の使用を要求することがあります。
  すべての要求をサーバが現在の状態で検証し、理由コード付きで拒否します。
- **リアルタイムの自由会話**: 発言順は固定しません。各AIが「今話すか」を判断し、生成中に状況が変わって
  古くなった発言は送らずに破棄します。8GB VRAMのGPU 1枚・LLMサーバ1つを9体で共有します。
- **会話品質の測定**: 「会話が成立したか」をモデルの自己申告ラベルで判定すると誤ることが分かり（後述）、
  サーバの盤面と書き起こしから機械的に測る方式へ作り直しました。
- **役職の追加にコード変更を要さないこと**: 「占い結果」「霊能結果」「勝利判定上の数え方」「陣営」を別の軸として持たせ、
  ゲームコアに役職名の分岐を書かずに13役職を表現しています。

## 4. システム構成

```
┌──────────────────────────────┐
│ Werewolf Server              │  ゲーム状態・ルール・進行・勝敗・公開範囲を唯一保持
│  aiwolf_core  ←→  network    │  行動要求の検証 / 公開・非公開イベントの振り分け
└──────────────┬───────────────┘
               │ WebSocket + JSON（JSON Schema v1.2で検証）
     ┌─────────┼─────────┐
 AI Agent × 9   （将来: 人間クライアント）   各自が知ってよい情報だけを受信
     │
 LLM Server（llama.cpp, OpenAI互換API）    全エージェントで1つを共有（RTX 3070 Ti 8GB想定）
```

ゲームコアはAIに依存せず、AIエージェントはサーバの内部モジュールを使いません。両者をつなぐのはプロトコルだけです。

## 5. 特徴

- **サーバ権威**: 状態・役職・生死・能力可否・勝敗はサーバだけが決定し、クライアントの申告は必ず検証（`Docs/ai/decisions/D001`）。
- **秘密はネットワーク配送段階で制限**: 公開・非公開イベントを配送経路で分け、死因も内部値と公開値を分離（D012, D020, D047）。
- **JSON Schemaによるバージョン付きプロトコル**: 送受信を両側で検証。厳密なヘッダと方向の区別（D031, D032）。
- **YAMLによるデータ駆動の役職**: `team` / `count_as` / `attack_result` / `inspect_result` / `medium_result` の5軸。
  人狼の仲間通知も「誰を仲間とするか」をYAMLで宣言し、サーバに役職名を書かない（D003, D009）。
- **複数AIエージェント × ローカルLLM**: 9体が独立したWebSocket接続で参加。発言前に短い判断JSON（確認した事実・狙い・理由）を作り、
  公開されない記録として保存。
- **リアルタイム自由会話**: 固定の発言順なし。発言のタイミング・破棄・反復フィルタ（`ai_agent/timing.py`, `repetition.py`）。
- **会話品質と秘密漏洩の機械チェック**: 完走・サーバ拒否・秘密本文や他人の結果の公開チャットへの混入・
  直前文の再使用・同一文3回以上・不適切な自己開示・死者への呼びかけ・生成時間を、ゲームごとに `checks.json` に出力。
- **反復検査と比較実験**: 改善案は最大3案を同じseedで比較し、基準を下回った案は通常のrevertで戻す運用（Git履歴に残っています）。
- **リプレイ**: 公開イベントだけから自己完結HTMLを生成し、試合一覧・検索・1〜50倍速再生（`ai_agent/replay.py`）。
- **長時間評価基盤**: 複数のローカルモデルを実ゲーム由来の12場面と実ゲームで比較し、
  9体の「感想戦」から教訓を作ってルール事実と照合する実験ランナー（中断・再開・締切管理付き）。

## 7. テスト状況

| 種類 | 件数・内容 | LLM |
|---|---|---|
| 単体・結合テスト | 385 tests / 809 subtests（ゲームコア、プロトコル、セッション、配送、AIエージェント、品質チェック、実験ランナー、リプレイ） | 不要 |
| 9体の完走テスト | 実サーバに偽のLLMを使う9体が接続して1ゲームを完走 | 不要（偽のLLM） |
| 別プロセス完走テスト（`-m completion`） | サーバとクライアントを別プロセスで起動し、プロトコルの行動とtickだけで完走 | 不要 |
| 実ゲーム評価 | `python -m ai_agent.play` で実モデルを使い、書き起こしと `checks.json` を出力 | ローカルLLMが必要（CIでは実行しない） |

GitHub ActionsではLLMを使わないテストだけを実行します（`.github/workflows/ci.yml`、Ubuntu: Python 3.10〜3.13、Windows: 3.13）。

## 8. 実行方法

```bash
python -m pip install -e ".[dev]"
```

```bash
python -m pytest -q
```

実モデルでゲームを回すには、OpenAI互換APIを持つ [llama.cpp](https://github.com/ggml-org/llama.cpp) の `llama-server` を
`127.0.0.1:8090` で起動しておきます（開発ではQwen3.5-9B Q4_K_M、コンテキスト8192を使用）。

```bash
llama-server -m <path-to-model>.gguf --host 127.0.0.1 --port 8090 -c 8192 -np 1 --jinja --reasoning off -ngl 99
```

```bash
python -m ai_agent.play --seed 1
```

`games/<日時>_seed<N>/` に書き起こし（`transcript.md`）と機械チェック（`checks.json`）が出力されます。
記録済みのゲームは `python -m ai_agent.replay` でHTMLのリプレイにできます。

長時間のモデル比較（`python -m ai_agent.marathon`）はWindows上の実験用ランナーで、
`AIWOLF_LLAMA_SERVER` と `AIWOLF_MODELS_DIR` でLLMサーバとモデルの場所を指定します。

### 再構築の判断（2026-10-02）

Phase 6では会話品質を上げるために、出力スキーマ・合成テスト・証拠保全の仕組みを積み重ねましたが、
2週間にわたり実ゲームが1回も行われていませんでした。原因を生ログと再実行で調べたところ、

- 「他人の発言に応答できたか」をモデル自身が付けたラベルで判定しており、そのラベルが出力形式の都合でほぼ必ず「NONE」になっていた
  （実際の本文には反論や意見変更があった）。**会話品質の問題ではなく測定器の欠陥**だった。
- 自前の長さ見積りが、モデルに届かない出力スキーマに上限の約半分を割き、会話履歴が1〜3件しか渡っていなかった。
- 「合成テストで100%合格するまで実ゲームに進まない」というゲートが、実ゲームでしか分からない問題を見えなくしていた。

同じモデルに普通の文章で指示する最小構成を実サーバにつないだところ、3ゲームとも完走し、サーバの拒否は0でした。
これを根拠に、検証済みのゲームコア・サーバ・プロトコルは残し、AI側を作り直しました。
分析と再現スクリプトは [`Docs/analysis/2026-10-02/`](Docs/analysis/2026-10-02/FINDINGS.md) にあります。

### AI支援開発について

このプロジェクトはCodex（OpenAI）とClaude（Anthropic）を使って開発しています。

- **人間（作者）**: 製品の要件とルールの決定（例: 会話を日本語にする、Phase 6の完了条件）、設計原則、
  評価基準と受入条件、実ゲームの書き起こしの確認、改善方針と再構築案の採否の判断。
- **Codex**: 主に実装・テスト・ゲーム実行・記録。
- **Claude**: レビュー、チェックポイントでの確認、停滞の原因分析（2026-10-02の分析はClaudeによるもの）。
- **ローカルLLM（Qwen）**: 2026-09上旬に開発補助・夜間の自動作業として試行し、その後廃止。

コミットの一部にはAIの共同作成者表記（`Co-Authored-By`）が残っています。
作業ルール（`Docs/process/AGENTS.md`）とロードマップ・作業記録（`Docs/process/`）も公開しています。
再構築前には、AIの役割を細かく分けて独立レビューを重ねる運用を試しましたが、手続き自体が仕事になったため、
現在は「実装担当1つ＋チェックポイントでの確認」という単純な形にしています（経緯は開発履歴を参照）。

## 10. 既知の課題

- 会話の質: 事実の取り違え（自分の役職や他人の結果の混同）がまだ残ります（`Docs/process/WORKLOG.md` の各ゲームのQ3/Q4）。
- 完了条件のうち人間判定の2項目は、引用候補を用意した段階で最終判定していません。
- Stage 3の教訓照合が受入基準未達で、長時間実験は保留中です。
- 長時間実験ランナーはWindows専用のAPI（プロセス監視・スリープ抑止）を使います。
- 再接続・AIを別PCで動かす構成・Web UI・人間の参加は今回の対象外です。
