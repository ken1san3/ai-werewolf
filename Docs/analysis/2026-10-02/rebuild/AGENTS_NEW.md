# AIwolf 開発ルール（2026-10 再構築版）

このファイルは、このリポジトリで作業するすべてのAI（Claude・Codex）への指示です。
旧ルール（6役割、Design Gate、独立レビューの連鎖、task packet、handoff）は廃止しました。
旧資料はGitタグ `archive/2026-10-02-*` にあり、通常の作業では読みません。

## 目的

複数のAIが、リアルタイムチャットで議論・推理・騙り・投票・能力使用を行う人狼ゲームを作る。
いまの最優先は「9人のAIが実際のサーバで1ゲームを最後まで遊び、会話として成立していること」。

## 役割

| 担当 | やること | やらないこと |
|---|---|---|
| ユーザー | 製品の決定、ゲームログを読んで良し悪しを判断 | — |
| Claude | 次の一手を決める、Codexへの作業指示、結果の確認、ユーザーへの報告 | 製品コードを直接書き換えない |
| Codex | 実装、テスト、ゲーム実行、結果の報告 | 指示の範囲外の変更 |

## 変えない設計原則

1. サーバが唯一の正しい状態を持つ。クライアントの申告は必ずサーバで検証する。
2. サーバとAIは別のプログラム。ゲーム本体はAIやLLMなしでテストできる。
3. 各プレイヤーには、知ってよい情報だけをサーバが送る。秘密をプロンプトで隠させない。
4. ゲーム本体に役職名の分岐を書かない。役職・陣営・プリセットはYAMLで定義する。
5. 会話はリアルタイムの自由発言。固定の発言順にしない。
6. プロトコルは言語非依存でバージョンを持つ。
7. RTX 3070 Ti（8GB）1台と共有LLMサーバ1台で動くこと。

## 作業の進め方

- AIの振る舞いを変えたら、必ず実際のゲームを回して確認する（`python -m ai_agent.play`）。
  報告には、ゲームの書き起こしのパスと機械チェックの結果を付ける。
- サーバ・プロトコル・秘密の配送を変えたら、テストを追加して `python -m pytest` を通す。
- 1回の作業は小さく。1つの変更 → ゲームまたはテスト → `WORKLOG.md` に1〜3行。
- 作業開始時に読むのは `AGENTS.md`、`README.md`、`ROADMAP.md`、`WORKLOG.md` の末尾、触るコードだけ。

## やらないこと

- 実ゲームの前に「合成テストで合格すること」を条件にしない。合成テストは回帰確認用。
- モデル自身が付けたラベル（発話の種類など）を合否に使わない。
- 証拠の来歴・保全を証明する仕組み、承認文書、独立レビューの連鎖、新しい運用文書を作らない。
  記録は `WORKLOG.md` だけ。
- アーカイブ済みのコード（旧 `ai_client/`、`scripts/`）を、ユーザーの了承なしに復元しない。
- 履歴の書き換え（`reset --hard`、force push、rebase）をしない。
- 未追跡のファイル（`logs/` など）を削除・移動しない。
- push は作業ブランチ `rebuild/simple-agent` への通常の push だけ。force push、main への push・merge、
  他のブランチやタグの push は、ユーザーの許可があるときだけ。

## 報告の書き方

- 日本語で、短く。最初に結論、次に「やったこと／やっていないこと／分からないこと」を分けて書く。
- 実行したコマンドと結果（PASS数・失敗内容）を書く。実行していないものを成功と書かない。
- 会話の質について書くときは、書き起こしから該当発言を1〜3行引用する。

## Phase 6 の完了条件（ユーザー決定 D072）

1つの実ゲームで次をすべて満たすこと。

1. 9人のAIで最後まで完走し、サーバが勝敗を確定する。
2. 他人の発言を受けた発言が1件以上ある。
3. 質問→回答、主張→反論、意見の変更のいずれかが1件以上ある。
4. private channel の本文、自分の非公開の結果、認証トークンが、公開チャットへ漏れていない。
5. 同じ人が直前と同じ文を繰り返さず、同じ文がゲーム全体で3回以上出ない。

判定方法: 1・4・5 は機械チェック。2・3 はユーザーが書き起こしを読んで確認する（AIによるラベル付けは補助）。
4 について「占い師が自分の結果を自分の意思で公表する」「人狼が自分から正体を明かす」を漏洩に数えるかは
未決定。ユーザーが決めるまでは、該当する発言を一覧で別に報告し、合否はユーザーに委ねる。
