## Q9 [Phase 2 前に必須] CO をシステム機能にするか

参照実装では **CO（カミングアウト）は自由発言ではなくシステム操作**で、
「市民騙り できる/できない」「CO回数制限 1日3回/制限なし」「2日目のCO できない/できる」
という設定を持つ。

マスター仕様には CO の概念が**一切存在しない**。

選択肢:

- A: 参照実装に合わせ、`co.declare` イベントをプロトコルへ追加する
  （回数制限をサーバが管理でき、AIの「占いCO」を構造化データで扱える）
- B: COは通常のチャット発言として扱い、COの検出はAI側の解釈に任せる
  （実装は軽いが、CO回数制限が実装できず、AIのCO判定が不安定になる）

Reviewer 推奨: **A**。マスター仕様 §34「AI出力はStructured Outputを優先」と整合し、
LLMが「誰が何をCOしたか」を毎回テキストから読み取る負荷も減る。

## Q10 [Phase 1] 投票ルールをどこまで Phase 1 で実装するか

参照実装の投票は単純多数決ではない（決選投票 / 処刑見送り / 無効票 / 自己投票）。

選択肢:

- A: Phase 1 で全部（設定で切替）
- B: Phase 1 は「多数決 + 同数時ルール」だけ実装し、
  処刑見送り・自己投票は Phase 8 へ回す

Reviewer 推奨: **B**。ただし `VoteResult` の型は最初から
「処刑あり / 処刑なし / 決選投票へ」の3値を返せるようにしておく。

## Q5 [Phase 1 中] 夜行動が未選択だった場合の既定挙動

参照実装は投票については「処刑見送り / 無効票」の設定を持つが、
夜行動（占い・護衛・襲撃）の未選択時の記述が見当たらない。

LLMは必ず失敗するのでサーバ側フォールバックが必要。

候補: ランダム選択 / 能力不発 / 前回対象を継続

Reviewer 推奨: **AI/Dummyクライアントはランダム、人間プレイヤーは不発**。
設定で切替可能にする。

## Q6 [Phase 2 前] プロトコルのバージョニングと順序保証

- 全メッセージに `protocol_version` を入れるか、ハンドシェイクのみか
- 再接続時の欠落検出用に `seq`（連番）を入れるか

後から足すのは高コストなので Phase 2 の最初に決める。

Reviewer 推奨: ハンドシェイクで `protocol_version`、全イベントに `seq`。
