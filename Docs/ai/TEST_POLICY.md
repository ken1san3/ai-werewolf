# Test Policy

各 Decision に散っていた検証項目を1箇所へ集約したもの。
設計そのものは `spec/DESIGN.md`、判断の理由は `decisions/`。

**各節の見出しに、その節を満たす責任を持つ Phase を書く。**
ROADMAP の「TEST_POLICY 全項目」は、**その Phase が担当する節**を指す。
まだ実装が存在しない層の項目を、前の Phase の完了条件にしない（Q36）。

原則:

- ゲームコアは LLM なしでテストできること
- 既定値に依存したテストを書かない。必要なルール設定を各テストが明示的に組み立てる
- 分岐のある設定は両方の値でテストする

---

## 1. データモデル［Phase 1.1］

- [ ] 13役職すべてが content の YAML だけで定義できている
- [ ] 属性を省略した役職が `team` から正しく導出される
- [ ] 狂人を占って「人狼でない」が返る
- [ ] 人狼を占って「人狼である」が返る
- [ ] 未実装の Effect / Passive を参照する定義が起動時にエラーになる
- [ ] 未登録の selector / restriction type を参照する定義が起動時にエラーになる
- [ ] `enabled_when` が不正な構文、または非boolのルールパスを参照するとエラーになる
- [ ] `effects` の省略形が Ability の priority を継承する
- [ ] `effects` で priority を明示した effect が別の priority で解決される
- [ ] 設定ファイルの不正値・順序未定義が起動時にエラーになる

## 2. Modifier［Phase 1.1］

- [ ] Modifier 0個のプレイヤーで、実効属性が Role の値と一致する
- [ ] テスト用 Modifier を付与すると、指定した属性だけが上書きされる
- [ ] `override` を持つ Modifier が勝利条件を置き換える
- [ ] `override` が競合する2つの Modifier の付与設定が起動時にエラーになる
- [ ] `duration: until_next_dawn` の Modifier が翌朝に解除される

## 3. フェーズ進行［Phase 1.3 / 突然死は 2.4］

- [ ] ゲーム開始直後のフェーズが Night0 である
- [ ] Night0 で人狼が襲撃を実行できない
- [ ] Night0 で人狼チャットが使える
- [ ] `first_night_seer: random_white` で Night0 にランダムな白判定が渡る
- [ ] `first_night_seer: none` で Night0 に占いが行われない
- [ ] Night0 で狩人が護衛した相手を Night1 で連続ガード制限なしに護衛できる
- [ ] 投票同数かつ `runoff: true` で Runoff へ入り、`false` では入らない
- [ ] `sudden_death.enabled: true` で、昼に一度も発言しなかった生存者が Day 終了時に死亡する
- [ ] 突然死した者が続く Vote に参加できない
- [ ] `sudden_death.enabled: false` で、昼に沈黙しても誰も死なない

## 4. 夜の解決［Phase 1.5］

- [ ] 占い師が襲撃された夜でも、その夜の占いが成立し呪殺が発生する
- [ ] 狩人が妖狐を護衛しても呪殺を防げない
- [ ] 妖狐を襲撃しても誰も死なない
- [ ] 妖狐を占うと妖狐が死ぬ
- [ ] 強欲な人狼の2人襲撃で、片方だけ護衛された場合に対象ごと独立に評価される
- [ ] `no_selection: random` の能力が未選択のとき、有効対象全員からランダムに発動する
- [ ] `no_selection: skip` の能力が未選択のとき、発動せず使用回数も減らない
- [ ] `rules.night_action.no_selection` が全能力の宣言を一括で上書きする
- [ ] 全員が未選択でも夜が解決し、フェーズが進む
- [ ] 標準 content で `no_selection: random` を宣言する Ability が襲撃能力だけである

## 5. 通知と情報漏洩［Phase 1.5 / 死亡者の範囲と再接続は 2.3］

- [ ] 妖狐を占った占い師が「人狼でない」だけを受け取る
- [ ] 占い師の受信イベントに呪殺を示す情報が一切含まれない
- [ ] 狩人が襲撃を防いだとき、狩人だけが GJ 通知を受け取る
- [ ] 狩人の護衛先が襲撃されなかったとき、狩人は何も受け取らない
- [ ] 護衛成功 / 妖狐襲撃 の2ケースで村側の受信イベントが同一になる
- [ ] 賢狼が襲撃成立時のみ対象の役職を受け取り、他プレイヤーは受け取らない
- [ ] 襲撃が護衛・耐性で失敗した場合、賢狼が何も受け取らない
- [ ] 強欲な人狼の2人襲撃で2人死亡した場合、賢狼が2件受け取る
- [ ] **内部死因の文字列がクライアント向けイベントに一切出現しない**（CI常時）
- [ ] `private.jsonl` の情報が `public.jsonl` に現れない
- [ ] 権限の無いチャットチャネルの内容がクライアントへ届かない
- [ ] パン屋が2人生存していても `PUBLIC_NOTIFY` は Dawn ごとに1回だけ発行される
- [ ] `PUBLIC_NOTIFY` の payload に `player_id` と人数が含まれない
- [ ] パン屋が全員死亡した翌 Dawn から `PUBLIC_NOTIFY` が発行されない
- [ ] `graveyard.reveal_roles: false` で、死亡者に他プレイヤーの役職が届かない
- [ ] 死亡者が受け取るイベントが、生存者が受け取る public イベントを超えない
- [ ] 再接続時、トークンが一致しない要求へ `game.state_sync` を返さない

## 6. 死因［Phase 1.4］

- [ ] 呪殺された妖狐の死亡通知がクライアント側で襲撃死と区別できない
- [ ] 夜の死亡が内部死因によらずすべて `died_in_night` になる
- [ ] 猫又の処刑時道連れが `died_in_day`、猫又本人が `lynched` になる
- [ ] content に新しい死因を追加しても、公開死因の導出コードを変えずにマスクされる
- [ ] `public_detail: cause` に切り替えると内部死因が公開される

## 7. 猫又［Phase 1.5］

- [ ] 襲撃されて死亡したとき、生存する人狼から1人がランダムに死ぬ
- [ ] 処刑されたとき、生存者から1人がランダムに死ぬ
- [ ] 処刑時の道連れ対象に人狼・妖狐・市民のいずれもが選ばれうる
- [ ] 抽選時点で猫又自身が候補に含まれない
- [ ] 狩人に護衛されたとき、道連れが発動しない
- [ ] 猫又Aの道連れで死んだ猫又Bの道連れが発動しない
- [ ] 道連れで死んだプレイヤーの `DeathCause` が `retaliation` になる
- [ ] 対象プールが空でも例外にならない
- [ ] 参照実装準拠（処刑時は生存者から）の猫又を YAML の変更だけで定義できる

## 8. 勝敗［Phase 1.6］

- [ ] 狂人が生存していても全人狼死亡で市民陣営が勝利する
- [ ] 狂人1・人狼1・市民1 で人狼陣営が勝利しない
- [ ] 人狼1・市民1 で人狼陣営が勝利する
- [ ] 最終日の処刑で最後の人狼が死亡した場合、市民陣営が勝利する
- [ ] 最終日に猫又を処刑し道連れで最後の人狼が死んだ場合、市民陣営が勝利する
- [ ] 人狼1・猫又1 で猫又を処刑し道連れで人狼が死んだとき `draw` になる
- [ ] `draw` のとき全プレイヤーの結果が `lost` になる
- [ ] 生存者0人が他のどの勝利条件よりも優先される
- [ ] `win_evaluation_order` を入れ替えると勝者が変わる
- [ ] 妖狐生存中に人狼が勝利条件を満たすと妖狐が勝つ
- [ ] 突然死で最後の人狼が死んだ場合、Day 終了時に市民陣営が勝利する

## 9. 行動の予約と解決［Phase 1.5］

- [ ] 夜の間に護衛先を3回送り直しても、解決されるのは最後の1つだけ
- [ ] 強欲な人狼が同時噛みを選んだあと通常襲撃へ戻すと `uses_remaining` が減らない
- [ ] 強欲な人狼が同時噛みを使った後、次の夜の `uses_remaining` が 0 になる
- [ ] 能力を送信した直後に `player.action_state` が再送されない
- [ ] `phase_ends_at` を過ぎた行動が拒否される
- [ ] 死亡プレイヤーが発言・投票・能力使用をできない

## 10. available_actions［Phase 1.7］

- [ ] Night0 の `player.action_state` に襲撃が含まれない
- [ ] `self_guard: false` で狩人の `valid_targets` に自分が含まれない
- [ ] `self_guard: true` で狩人の `valid_targets` に自分が含まれ、自己護衛が成立する
- [ ] `self_guard` の true / false で、列挙と検証が同一の宣言から導かれる
- [ ] 連続ガード「なし」で前夜の護衛先が `valid_targets` から外れる
- [ ] 連続ガード「あり」「なし」の両方で同一のゲームコアがテストを通る
- [ ] 死亡プレイヤーの `player.action_state` が空になる
- [ ] ネットワーク層を経由しないコアのテストで結果が同一になる
- [ ] Modifier が付与するチャットチャネルが `player.action_state` に現れる
- [ ] CO 操作が列挙されるのは、`allows_co` を持つチャネルへの発言が列挙されるときだけである
- [ ] 公開チャネルの ID を改名しても、Python を変更せずに CO が列挙される

## 11. 投票［Phase 1.3］

- [ ] 「決選投票あり → 再同数 → 処刑なし」が動く
- [ ] 「決選投票なし → ランダム処刑」が動く
- [ ] `self_vote: false` で自分が候補に含まれない
- [ ] `no_selection` の2値がそれぞれ正しく動く

## 12. CO［Phase 2.4］

- [ ] 回数制限を超えた `co.declare` が拒否される
- [ ] 人狼が実際とは異なる役職をCOでき、サーバが拒否しない
- [ ] 死亡プレイヤーがCOできない
- [ ] `allow_villager_claim: false` では `claimable: false` の Role がCO候補に現れず、指定すると拒否される。`true` では候補に現れる
- [ ] CO候補はその試合の配役に含まれる役職だけで、配役に無い役職は候補に現れず指定しても拒否される
- [ ] `content/roles/` に役職を1つ足しても、進行中の試合のCO候補が変わらない
- [ ] `role_missing.enabled: true` で役職が欠けても、CO候補は preset の配役のままで変わらない（欠けた役職が候補から消えない）
- [ ] `claimable` を宣言しない Role は content load でエラーになる
- [ ] `claimable: false` の Role ID を改名しても、Python無変更で同じ候補除外・拒否になる
- [ ] `chat.send` は利用可能チャネルが1件でも `channel_id` を必須とする
- [ ] 列挙されていない `channel_id` は `action_unavailable` で拒否される

## 13. ログとリプレイ［Phase 1.8］

- [ ] 1試合を実行し、`public.jsonl` だけでゲーム経過を追える
- [ ] ランダムな選択の結果がイベントとして残っている
- [ ] 固定 RNG を注入したテストが安定して通る
- [ ] モジュールレベルの `random` を直接呼んでいる箇所が存在しない（静的チェック）

## 14. 拡張性［Phase 1.8］

- [ ] 役職を1つ追加するのに Python の変更が不要
- [ ] 狂人 / 狂信者 / 囁く狂人 がゲームコアの分岐なしに区別される
- [ ] 人狼 / 強欲な人狼 / 賢狼 が同一属性で Ability だけの差として表現される
- [ ] content が宣言する ID（role id / tag / team id / channel id / death cause id）が `server/aiwolf_core/` に直書きされていない（静的チェック）
