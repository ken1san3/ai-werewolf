## A. マスター仕様 — Critical

### A-1. `team` が「勝利陣営」と「占い判定」を兼ねている

§7 / §9 / §31 では役職に `team` しか持たせていない。しかし:

| 役職 | 勝利陣営 | 占い判定 |
|---|---|---|
| 狂人 | wolf | 白（村） |
| 妖狐 | fox | 白（村） |
| 人狼 | wolf | 黒 |

`team` 一本で実装すると狂人が黒判定になる。§31は「狂人をどう判定するかは
ルール設定化できると望ましい」と書いてあるだけで、モデル上の解決策が無い。

§32 の抽象化リスト（Role/Team/Knowledge/Ability/Passive/Effect/WinCondition/
ChatPermission）にも `Alignment`（見え方）が欠けている。

→ **`team`（勝利）と `alignment`（判定上の見え方）を分離する。** OPEN_QUESTIONS Q1。

### A-2. 村の勝利条件が狂人で成立しない

§10 の村:

```yaml
win_conditions:
  - type: eliminate_team
    target: wolf
```

狂人が `team: wolf`（§31で明記）なので、**狂人が生き残っている限り村が勝てない**。
`eliminate_team` は実際には「襲撃能力を持つ役職の全滅」を意味している。

→ 勝利条件の対象を陣営ではなくタグ/役職集合にする。OPEN_QUESTIONS Q2。

## B. マスター仕様 — 仕様の抜け（Phase 1 で必要）

### B-1. ゲームルールの既定値が丸ごと未定義

以下は人狼で最も揉める部分だが、仕様に一切記述が無い。

```
初日処刑の有無
初日占い（自由 / ランダム白 / なし）
初夜襲撃の有無
投票同数時（決選投票 / ランダム / 処刑なし）
連続護衛の可否
狩人の自己護衛の可否
霊能結果の通知タイミング（当夜 / 翌朝）
複数狼の襲撃先決定（多数決 / 指定役 / ランダム）／同数時
```

「設定化する」とは書かれているが**既定値が無い**ため、実装者が勝手に決めると
後で全部やり直しになる。OPEN_QUESTIONS Q3。

### B-2. 勝敗判定のタイミングが未定義

§10 の `parity`（狼数 >= 村人数）を、処刑直後 / 襲撃直後 / 朝 のどこで評価するかで
最終日の結果が変わる。§6のイベント列に `GAME_END_CHECK` はあるが、
どのイベント後に発火するかが書かれていない。OPEN_QUESTIONS Q4。

### B-3. 行動未選択・タイムアウト時の既定挙動が無い

占い師・狩人・狼が時間内に対象を選ばなかった場合の扱いが未定義。
LLMは必ず失敗するので、Phase 1 の時点でサーバ側フォールバック
（ランダム / 不発 / 前回継続）が要る。OPEN_QUESTIONS Q5。

### B-4. §11 の解決順に「非解決系能力」が混ざっている

§7 の werewolf 定義で `wolf_chat` が `timing: night` の ability になっているが、
これは Effect を解決する能力ではなく ChatPermission である。
§32 が「AbilityとChatPermissionを分離せよ」と言っているのと矛盾する。

→ `wolf_chat` は ability ではなく `chat_channels: [public, wolf]` として持たせる。

## C. マスター仕様 — ネットワーク（Phase 2 で効いてくる）

### C-1. プロトコルにバージョンが無い

§4.2 の共通フィールドは `type / event_id / game_id / timestamp / payload`。
§28 で「将来 C++ / TypeScript / Rust クライアントが接続可能であること」と
掲げている以上、`protocol_version` は最初から入れるべき。後付けは高コスト。

### C-2. 状態同期イベントが無い

§40 で「再接続」は将来候補扱いだが、`game.state_sync`
（自分が知ってよい現在状態のスナップショット）は
**遅れて接続したクライアント・観戦者・UI 起動時にも必要**で、
Phase 2 の設計に最初から入っていないと後で大改修になる。

### C-3. 順序保証・欠落検出手段が無い

WebSocketは順序保証されるが、切断中に落ちたイベントの検出には連番が要る。
`seq` を入れておくとリプレイ（§25）とも整合する。

### C-4. ログの公開/秘匿分離が §27 と衝突しうる

§24 は「秘密チャット・AI内部判断・LLM入出力を全部保存」、
§27 は「秘匿情報を漏らすな」。同一ログファイルに書くと、
観戦UI・リプレイ・デバッグ共有の段階で漏れる。
`public` と `private` を最初からファイル分割する方針を明記した方がよい。

## D. マスター仕様 — リアルタイム性（Phase 5 で効いてくる）

### D-1. 同時発言の抑制手段が無い

§3.2 の反応スコアはクライアント側の判断で、§36 のクールダウンも個体単位。
「重要な発言が出た瞬間に9体全員のスコアが上がって一斉に喋る」ケースへの
対策がどこにも無い。サーバ側の発話レート制限か、クライアント側のjitterが要る。

### D-2. 昼フェーズの終了条件が未定義

固定秒数か、全員が発言意欲を失ったら短縮するか。
AI 9体だとLLM生成レイテンシが議論時間を支配するため、ここは実測前提。

### D-3. LLM推論量の見積りが無い

§18 は「8GB VRAMで共有LLMサーバ」とあるが、
7B級・共有1台なら1推論あたり数秒、昼60秒で全体10〜20発言が現実的上限。
これは §3 の「リアルタイム自由チャット」の密度を直接決めるので、
Phase 5 前に実測して数値を仕様へ書き戻すべき。OPEN_QUESTIONS Q8。

§28 の「人間がセッション開始プロンプトを貼る」運用は残すべき。

# 追補 2026-08-29 — 人狼ジャッジメント調査後

参照実装の公式仕様を確認した結果、上記レビューに**追加・訂正**が必要になった。
詳細は `spec/JUDGMENT_REFERENCE.md`。

## 訂正

### A-1 の訂正 — 軸は2つではなく5つ

初版で「`team` と `alignment` の2分離」と書いたが、**不足**だった。

- **大狼**: 占い結果=人狼でない / 霊能結果=人狼である
  → 占い結果と霊能結果は1つの `alignment` にまとめられない
- **狂人**: 勝利陣営=人狼陣営 / 陣営カウント=市民として数える
  → 勝利陣営と人数カウントも別の軸
- **狐憑き**: 全属性が「役職に準ずる」→ 委譲値が必要

正しい分離は `team` / `count_as` / `attack_result` / `inspect_result` / `medium_result`
の5軸。`decisions/D003` を正とする。

### A-2 の補足 — 参照実装の勝利条件

市民陣営は「全人狼死亡時」、人狼陣営は「『市民』の数を『人狼』の数以下にする」。
前者は**役職タグの全滅**、後者は**`count_as` の人数比較**であり、型が違う。
`decisions/D005` で確定。

## 追加指摘

### H-1 [High] CO がシステム機能であることがマスター仕様に無い

参照実装では CO は専用操作で、「市民騙り」「CO回数制限 1日3回」「2日目のCO」
という設定を持つ。マスター仕様には CO の概念が一切無い。
`OPEN_QUESTIONS.md` Q9。

### H-2 [High] ルール設定が2層構造である

参照実装の設定は「グローバル設定」と「役職固有ルール（数十項目）」に分かれる。
マスター仕様 §2 の config 例は `players` と `roles` の人数だけで、
役職ごとのオプションを持てる構造になっていない。

→ 役職YAMLに `options:` を持たせ、コアはその意味を知らない形にする。

### H-3 [Medium] 投票が単純多数決ではない

決選投票 / 投票同数でランダム処刑 / 処刑見送り（0〜2回）/ 投票未選択時の扱い /
自身への投票 の5設定が絡む。マスター仕様の VOTE 系イベントは
`VOTING_STARTED / VOTE_CAST / VOTING_ENDED / PLAYER_LYNCHED` のみで、
決選投票の再ラウンドを表現できない。`OPEN_QUESTIONS.md` Q10。

### H-4 [Medium] 昼フェーズは固定時間ではない

参照実装は「時間延長 なし〜5回（1回2分）」「時短・延長成立人数 全員/過半数」を持つ。
D-2 で指摘した「昼フェーズの終了条件が未定義」の答えは
**固定時間ではなく、プレイヤー合意で伸縮する**。
AI 9体の場合、この合意を誰がどう出すかを Phase 5 で決める必要がある。

### H-5 [Low] 15秒ルール

夜明け直後の発言を禁止する設定がある。
リアルタイムチャット制御の一部としてサーバ側に持たせるのが自然。
AIが夜明け直後に一斉発言する問題（D-1）の緩和にもなる。

### H-6 [Low] 役職欠け

「ランダムに役職が市民に置き換わる」設定。役職配布ロジックに影響する。
Phase 1 の役職配布で考慮しておくと後が楽。

### H-7 [Low] 霊能の判定対象は「処刑・突然死した人」

処刑者だけでなく突然死も対象。また判定結果は真偽2値ではなく
「人狼 / 人狼でない / 大狼 / 子狐 / 悪魔の眷属」の**タグ**。
`medium_result` を bool にしないこと（`decisions/D003`）。

## 良い点（追加）

マスター仕様 §32 が「Role / Team / Knowledge / Ability / Passive / Effect /
WinCondition / ChatPermission を混同しない」と言っているのは方向として正しく、
参照実装の狂人 / 狂信者 / ささやく狂人がまさに
「陣営は同じ・知識が違う・チャット権限が違う」だけの3役職として存在する。
この3つを1つの `if` で分岐せずに表現できれば、設計は正しい。
