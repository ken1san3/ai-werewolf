# Phase 6 停滞の構造診断と改善提案

Status: PROPOSAL（外部レビュー。未承認。製品変更0、provider操作0、新規生成0）
作成: 2026-09-24
作成者: Claude Code

## 結論

1. **停滞の主因は候補の質ではなく、採否ゲートにある。** 現行の「全指標非悪化・相殺不可・
   1 seed・n=32」ゲートは、基準と全く同じ性能の候補ですら概算1〜5%しか通さない。
   主要5軸で改善したGB1も、標本誤差の範囲内の差で不採用になっている。
2. **解決の部品は、既に不採用になった候補の中に散らばっている。** 捏造0で最良のHARDを
   出したGB1、秘密開示を0〜1へ下げた段階生成（I1・最小出力・導出grounding）。
   ゲートが個別に棄却したため、組み合わせが一度も試されていない。
3. **現行ルールの中でGPTが次の候補を試しても、同じ結果になる可能性が高い。**
   類似事例で効いている手段（生成後フィルタ、groundingの入力化、モデル選択、段階分離）の
   多くを、現行のholdと採否規則が禁じている。次に必要なのはユーザーによるルール判断である。

## 2. 停滞の構造的原因

### 2.1 採否ゲートは基準と同性能の候補すら通さない

D078は「改善指標との相殺は認めない」とし、K1判定は6指標の各々非増加を要求している。
各候補は1 seed・32件であり、`旧baseline/候補の再生成・再採点なし` のため基準側の揺らぎも測れない。

真に同等な2つの標本を1回ずつ比べたとき、候補側が厳密に悪く見える確率 q を二項分布で計算した。

| 指標（基準値相当） | q |
|---|---:|
| 秘密開示 5/32 | 0.43 |
| HARD fail 14/32 | 0.45 |
| act/text不一致 23/32 | 0.44 |
| 質問回答 9/18 | 0.43 |

指標を独立と仮定した概算では、非悪化を6指標で要求すると通過率4.7%、8指標で1.7%になる。
指標間の相関はこの値を上げるが、桁は変わらない。**基準自身を再測定しても、ほぼ確実に不採用になる。**

GB1の不採用理由になった差は、いずれも95%区間（Clopper-Pearson）が完全に重なる。

| 理由 | 基準 | GB1 |
|---|---|---|
| 秘密開示 | 5/32 [5%, 33%] | 6/32 [7%, 36%] |
| 質問回答 | 9/18 [26%, 74%] | 5/18 [10%, 53%] |
| 合法NONE | 2/2 [16%, 100%] | 0/2 [0%, 84%] |

同じ構造でI1も不採用になっている。I1は秘密開示を5→1へ下げ、HARDを悪化させなかったが、
act/text不一致の23→24（1件差）で必須条件不達とされた。

最終受入（D077）はHARD 100%・重大秘密/状態矛盾0を要求する。9B・4bitの1回生成で
32件の敵対的caseを全て通すことを要求しており、4節U2の生成後フィルタ無しでは到達が難しい。

### 2.2 1回の生成に「聞く・考える・話す・ラベル付け・接地」を詰め込んでいる

現行の1 callは、本文に加えて12項目のdiscussion proposal（評価更新、claim更新、関係更新、
戦略、CO判断、反応、接地参照付きspeech_act）を生成する。条件は次のとおり。

- 9B・Q4_K_M、`enable_thinking=false`、出力上限512 token
- schemaはgrammarとしてのみ効き、prompt本文には入らない（T406実測）
- `response_format.json_schema` / `strict: True` の制約付きdecode

類似事例（3節）はこれらを分けている。LLMに参照を生成させると、避ける（NONE）か作る（捏造）かの
二択になることが、1節の表で繰り返し観測されている。

### 2.3 実験1回あたりの手続きが重い

test-onlyの候補1つが、設計→独立設計review→tool実装→独立tool review→freeze→一回測定→
独立意味評価→decision→archiveを通る。1候補あたり約6 packet・約10 handoffになり、
得られる結果は1 seed・32件の1標本である。検出力が低く、1回の費用が高い組み合わせになっている。

D068は同一目的の失敗3round後に経路再評価を要求するが、実施された再評価
（`PHASE6_HYPOTHESIS_FRONTIER_20260922.md`）は候補仮説の列挙に留まり、
ゲートとholdそのものを再評価の対象にしていない。

### 2.4 補足: speech_actはクライアントの外に出ない

`server/`・`protocol/` に `speech_act` の参照は無い。製品コードでの用途は
`ai_client/discussion/state.py` の自己検証と、自分の直近記録 `RecentSemanticTurn` への保存だけである。
他のplayerが見るのは本文、serverが受け取るのは行動である。

12候補の多くが主対象にしたact/text不一致は、ゲーム進行にも他playerにも届かない自己注釈の誤りである。
人狼知能大会の自然言語部門も、発話の自然さ・文脈適合・一貫性・行動と対話の整合・表現の豊かさで
評価しており、発話行為ラベルは評価対象にしていない。

## 3. 類似事例

| 事例 | 構成 | 本プロジェクトとの差・示唆 |
|---|---|---|
| CICERO（Meta, Science 2022） | 戦略モジュールが意図を決め、対話モデルは意図を条件に発話を生成。複数候補を生成しfilterで除外 | 意図と接地は生成の**入力**。1回で当てず、生成してから捨てる |
| Listener / Thinker / Presenter（Wu et al., arXiv 2402.02330） | 発話理解・推論・発話生成を分離。9人人狼で、fine-tuneした6B LLMをThinkerと組み合わせるとGPT-4を上回った | 小型モデルでも役割を分ければ届く。現行は1 callが全役割を担う。ただしThinkerは人間対局18,800件とRLで学習した専用モジュールであり、そのまま移植できるわけではない |
| LLM候補生成＋RL選択（Xu et al., ICML 2024, arXiv 2310.18940） | LLMが推論し多様な行動候補を出し、別の方策が選ぶ | 候補生成と選択の分離。LLM単独の選択には偏りが出る |
| ReCon（Wang et al., arXiv 2310.01320） | Avalonで、発話案の作成（formulation）と他者視点での推敲（refinement）を分ける | 秘密開示への対策は発話前の段階分離。1節で段階生成の秘密開示が下がった観測と整合 |
| Let Me Speak Freely?（Tam et al., arXiv 2408.02442） | 形式制約が厳しいほど推論性能が落ちる。自由生成→形式変換で緩和 | 厳格な巨大schemaで一発生成する現行方式の弱点に一致 |
| Werewolf Arena（Bailis et al., arXiv 2407.13943） | 入札（bidding）で誰がいつ話すかを決める動的turn-taking | 「話すかどうか」を発話内容と別の判断にできる。チーム自身の仮説H03（`PHASE6_HYPOTHESIS_FRONTIER_20260922.md`）と同じ論点 |
| 人狼知能大会（プロトコル部門・自然言語部門） | 構造化された発話行為は専用プロトコル、自然言語部門は本文のみで評価 | 現行はLLMに両方を同時に出させている。COは既にsystem操作（D007）で構造化済み |

## 4. 改善案

### ユーザー判断が必要なもの

以下は現行のhold・D077・D078に抵触するため、GPTは自分では選べない。

| # | 判断 | 根拠 |
|---|---|---|
| U1 | **採否ゲートの作り直し。** 主指標を1つ事前登録し、副指標は非劣性マージンで判定。候補と基準を同じ3 seed以上で測る。相殺を認める範囲を事前に決める | 2.1節。現行ゲートは基準自身を通さない |
| U2 | **生成後フィルタと再サンプルの製品採用。** 既存validatorと機械的検査を通るまで最大K回生成する（早期終了） | CICERO。1回生成でHARD 100%は困難だが、機械検出できる失敗は除外できる |
| U3 | **接地の入力化の許可。** 受信済みの構造化state（本人能力結果、CO宣言、生死、自分宛ての未回答発話）から、コードが候補を番号付きで提示し、LLMは番号を選んで本文を書く | GB1が唯一捏造0。現holdの「本文/regexからのref推定禁止」の範囲確認が必要 |
| U4 | **speech_actの位置付け。** 受入の主指標から外すか、本文生成後の別の小さな分類へ移すか | 2.4節。クライアント外に出ない自己注釈 |
| U5 | **モデル比較1回の許可。** 最良候補をQwen3.5-9BとGemma3-12Bで、同じ事前登録条件で比べる | T427でGemmaはHARD fail 7（Qwen 14）、秘密開示0（Qwen 5）。約30秒/発言の遅延は別評価 |

U3の「自分宛ての未回答発話」だけは本文を見る必要があり、現holdの禁止範囲に触れうる。
本人能力結果・CO宣言・生死は既に構造化されており、本文推定を伴わない。

### ルール変更後にGPTが実行できるもの

| # | 作業 | 前提 |
|---|---|---|
| G1 | 既存GB1を新ゲートで再判定する。GB1と基準を同じ3 seedで測る | U1 |
| G2 | GB1に生成後フィルタ（U2）を重ね、機械検出可能なHARD失敗の残りを測る | U1・U2 |
| G3 | 段階生成（意図→本文）とGB1の接地方式を組み合わせる。秘密開示の低下と捏造0の両立を確認 | U1・U3 |
| G4 | test-only候補の手続きを軽量化する。製品を変えない探索はMain単独で測定・記録し、独立chainは採用時だけ通す | U1 |

## 5. 推奨する進め方

1. U1を決める。**これが無い限り、どの候補を試しても採否結果の意味が無い。**
2. G1: GB1を新ゲートで再判定する。既存の承認済みtoolで実施でき、新規設計は不要。
3. G2: GB1＋生成後フィルタ。機械検出可能な失敗がどこまで消えるかを測る。
4. 残る失敗（質問への回答不足、秘密開示の一部）を見てG3かU5を選ぶ。
5. 条件を満たしたら、D077の順序どおり短い実gameへ進む。

質問への回答（最良でも11/18）は12候補のどれでも大きく改善していない。
これは本提案の対象外の独立課題として残る。

## 6. GPTへの渡し方

現行ルールのままGPTへ「次の候補」を依頼すると、同じ箱の中で13番目の候補が作られる可能性が高い。
次の3点を指示に含めると、箱の外に出られる。

1. 本文書のU1〜U5のうち、ユーザーが許可した項目を明記する。
2. D068の経路再評価は、候補仮説だけでなくゲートとholdも対象にすることを明記する。
3. test-only探索にはG4の軽量手続きを適用し、採用時にだけ独立chainを通すことを明記する。

## 7. 限界

- 1節の数値は各handoffとdecisionの転記であり、保存rawを再採点していない。
- 2.1節の確率は二項分布による概算で、指標の独立を仮定している。
- 類似事例は会話ゲームの近縁研究であり、本プロジェクトの条件（9B・8GB・9 agent共有・英語）で
  同じ効果が出ることは未検証である。
- U3の接地入力化が、合法な騙りや自由な推理を狭めないかは設計時に確認が要る。
- 本提案はprovider・実game・製品コードを操作していない。
