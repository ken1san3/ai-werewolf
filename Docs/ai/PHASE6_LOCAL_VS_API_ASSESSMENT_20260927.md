# Phase 6 ローカルLLM継続とAPI移行の段階評価

Status: FINDINGS（外部レビュー。未承認。製品変更0、provider操作0、新規生成0）
作成: 2026-09-27
作成者: Claude Code

## 結論

**段階1（ローカルで解決可能か）: 「解決不能」とはまだ言えない。**
成功した類似事例が共通して使っていた構造上の手段が3つ未試行で、いずれもモデル変更なしで試せる。

**段階2（APIを使うべきか）: APIは構造対策の代わりにならない。**
GPT-4o級を使った大会参加チームでも、本プロジェクトと同じ失敗（秘密の漏洩、応答不全、反復）が報告されている。
コストは判断要因にならないほど小さい。導入するなら、段階1の構造対策後も能力不足が残った場合に、
置き換えではなく選択可能なバックエンドとして入れる。

## 段階1: ローカルLLMで解決可能か

### 最も近い類似事例: 人狼知能大会 2024冬季・自然言語部門

主催者の概要論文（狩野ほか、言語処理学会第31回年次大会 D7-1、CC BY 4.0）による全7チームの構成。

| チーム | モデル | 構成の特徴 | 勝率macro | 主観評価順位平均 |
|---|---|---|---:|---:|
| UEC-IL | gpt-4-turbo / 4o / 3.5-turbo を用途別 | 日ごとの要約、ペルソナ | 56.58 | 2.433 |
| kanolab | GPT-4o | 会話から役職関係を抽出し、論理情報をLLM外で構築してから発話生成 | 56.29 | 2.850 |
| **Mille** | **Llama-3-ELYZA-JP-8B GGUF（ローカル）** | 直前2発話のみ、宛先付き発話に返信、人狼・狂人にはLLMへ偽の役職を渡す | **51.30** | 2.890 |
| sUper IL | GPT-4o-mini | 状況分析・応答・説得・投票の4モジュール | 50.34 | 2.925 |
| CanisLupus | Gemini 1.5 Flash | 生成後に口調変換の2回目呼び出し | 49.66 | 2.621 |
| barneko | GPT-4o-mini | 立場抽出→戦略→発話 | 46.90 | 2.829 |
| satozaki | gpt-4o-mini | 分析・戦略（ルールベース）・生成・投影に分割 | 44.16 | 3.014 |

- ローカル8BのMilleが、API勢3チームより高い勝率を出した。ただし大会は5人村で、本プロジェクトの9人村より単純。
- 上位チームは全て処理を分割している。1回の呼び出しで全てを出させた構成は無い。
- 主催者は、単一LLMセッションでは意図的に嘘をつけない、話がかみ合わない、同じ主張の繰り返し、
  役職名を何度も問い詰めると答えてしまう、という共通課題を報告している。

### その他の類似事例

| 事例 | 要点 |
|---|---|
| GREE（人狼知能大会2026春季） | Gemini 3 Flash採用。ローカルGemma 4 26Bは並列リクエストで遅く不採用、Flash Liteは出力形式を守れず不採用。推論と発話を非同期に分離して戦略と表現が大きく改善 |
| GREE（同2025春季） | Gemini 2.5 Flash。勝率1位だが会話の流れを無視する問題が残った |
| Listener/Thinker/Presenter（Wu et al., arXiv 2402.02330） | fine-tuneした6Bと専用推論モジュールでGPT-4を上回った。推論モジュールは人間対局18,800件とRLで学習 |
| NVIDIA ACE（PUBG Ally、inZOI） | 商用ゲームで0.5B〜8Bをローカル実行。ただし指示応答中心で、欺瞞を含む多人数議論ではない |
| Foaster Werewolf Benchmark | 210ゲームでGPT-5が首位。戦略的な強さはモデル能力に比例する |

### 本プロジェクトの実測

T506では、Qwen 9Bのまま出力契約だけを変えたGB1が、秘密開示14→1、捏造4→0、HARD失敗27→10を示した。
契約変更でローカルモデルの安全面は大きく改善した。残る不足は質問への応答と、発話意図と本文の一致である。

### 未試行の手段

| # | 手段 | 前例 | 効く失敗 |
|---|---|---|---|
| L1 | 発話を生成する呼び出しに真の役職を渡さない | Mille、Thinker/Presenter | 秘密開示（知らない秘密は漏らせない） |
| L2 | チャットのプロトコルに宛先フィールドを加える | 人狼知能大会の `>>Agent[01]` アンカー | 質問への応答 |
| L3 | 最終段は本文だけを生成し、発話意図は前段で決めて入力として渡す | kanolab、satozaki、GREE 2026、CICERO | act/text不一致、応答不全 |

L2の根拠: `protocol/aiwolf-v1.1.schema.json` のチャットメッセージは `channel` と `message` だけを持つ。
LLMが質問の宛先を生成しても、それはクライアント外に出ないため、受け手は自分宛ての質問を構造的に知れない。
本文からの推定はholdが禁じており、T506で「本人宛て未回答」候補集合が未実装のまま残った理由でもある。

L3の根拠: 段階化した候補（P2、IC2、GB1）は、いずれかの段で旧来の出力契約を生成し続けていた。
T506結果文書も「GB1は依然として後段でlegacy full outputを生成する」と記録している。

L1の注意: Milleは騙る役職をコードで固定したが、本プロジェクトは騙りをルールで固定しない方針である。
真の役職を見る段がLLMとして騙りを判断し、発話段はその結果だけを受け取る形で方針と両立させる。

### 段階1の判定

L1〜L3を試すまで、ローカルで解決可能かは決められない。進め方と停止条件は
`design/PHASE6_LOCAL_STAGED_DISCUSSION_DESIGN.md` に記載する。
ローカルモデルのfine-tune（LoRA）も前例上有効だが、holdの「モデルDL禁止」に触れ工数も大きい。

## 段階2: APIを使うべきか

### APIで解決すること・しないこと

| 解決する | 解決しない |
|---|---|
| 推論の深さ・戦略の強さ | 秘密の漏洩（GPT-4o級でも問い詰められると答える） |
| 速度（9エージェントを並列処理。ローカルは同時1リクエスト、Qwenは1call p50 5.45秒） | 話がかみ合わない、同じ主張の繰り返し |
| モデル固有の癖（Gemmaの整形出力など） | 宛先が伝わらない（プロトコルの問題） |

### コスト試算

T506実測の1callあたり入力1,721・出力213 tokenと、1ゲーム150〜200 call（T389は4日目投票まで117 call）を前提にする。
価格はAnthropic公式価格。

| モデル | 入力 / 出力（$/100万token） | 1ゲーム |
|---|---|---:|
| Claude Haiku 4.5 | $1 / $5 | 約$0.4〜0.6 |
| Claude Sonnet 5 | $2 / $10 | 約$0.8〜1.1 |
| Claude Opus 5 | $5 / $25 | 約$2.1〜2.8 |

段階構成でcall数が2〜3倍になっても1ゲーム数ドルに収まる。32件人工suiteはOpus 5でも1回約$0.5。
他社の同等クラスも同じ桁だが、価格は頻繁に変わるため導入時に確認する。

### 互換性と設計上の衝突

| 項目 | 状況 |
|---|---|
| schema | 現行8,202 bytes、プロパティ計93、入れ子最大4段、`oneOf` 3箇所。Anthropicのstructured outputsは`anyOf`・`$ref`に対応するが`oneOf`は対応リストに無い。本schemaの`oneOf`は`kind`定数で排他なので`anyOf`へ機械的に置換できる。OpenAIは公開情報でプロパティ100個・入れ子5段等の上限があるとされ、93個は余裕が小さい（要確認） |
| コード | `ai_client/llm/types.py` の接続先検証がループバックのhttpだけを許可する。意図的なセキュリティ境界で、変更にはAPIキー管理を含む設計が要る |
| 設計不変条件9 | 「RTX 3070 Ti / 8GBで1台のLLMサーバを共有」と衝突する |
| 再現性 | APIモデルは更新される。SHA凍結と同一seed再現を前提にした証拠運用をモデルID記録中心に変える必要がある |
| 将来の人間参加 | 人間プレイヤーの発言が外部に送られる。プライバシー方針が必要 |

READMEは「異種LLM対戦」を目標に掲げている。APIを選択可能なバックエンドとして追加し、
ローカルを既定のまま残せば、この目標と不変条件9の両方を保てる。
推論段だけ強いモデル、発話段はローカル、という混成も可能である。

## 段階1から2への判定を早める診断（任意）

既存の32件人工suiteをAPI上位モデルで1回流すと（Opus 5で約$0.5）、上位モデルも現行契約で失敗するなら
問題は契約側と確定し、あっさり通るなら容量不足が本質と分かる。
合成データの外部送信とテスト専用の接続経路が必要で、ユーザー判断を要する。

## 限界

- 大会の構成と成績は5人村のもので、9人村の本プロジェクトに同じ効果が出るとは限らない。
- コスト試算は1ゲームのcall数を仮定しており、実測ではない。
- API側のschema制約は公開資料の記載であり、実際の受理可否は未検証。
- 本評価はprovider・実game・製品コードを操作していない。
