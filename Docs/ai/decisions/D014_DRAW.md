# D014 引き分け（全員敗北）を勝敗結果の型に含める

Status: Accepted (2026-08-29) / ユーザー決定

## Context

D005 に引き分けの規定が無かった。13役職の構成では実際に発生する。

```
残り2人（人狼1・猫又1）→ 猫又を処刑 → 道連れで人狼が死亡 → 全員死亡
```

この時点で市民陣営の条件（全人狼死亡）も人狼陣営の条件（0 ≤ 0）も同時に成立しうる。

## Decision

`outcome` に `draw` を含め、**全員敗北**として扱う。
生存者0人は他のどの勝利条件よりも優先して `draw` とする。
同時成立の優先順位は `win_evaluation_order` として設定に持つ。
詳細は `spec/DESIGN.md` §8。

## Why

- あとから足すと勝敗判定・ログ・リプレイ・将来の戦績すべてに波及する
- 「全員勝利」だと将来レーティングを入れたときレート計算が破綻する
- 評価順を設定にしたことで、第三陣営を足しても判定コードを変えずに済む

## Consequences

勝利条件評価器は「勝者なし」を返せる必要がある。
Phase 8 で恋人陣営（複数勝者）を足すとき `winner_team` を複数へ広げる必要が出る。
