# D011 猫又の道連れ仕様

Status: Accepted (2026-08-29) / ユーザー決定

## Context

参照実装の猫又は襲撃時と処刑時の両方で道連れを発動する。
本プロジェクトでもほぼ同等とするが、**道連れによる死亡では発動しない**制約を加える。

## Decision

死因によって発動可否と対象プールが変わる。

| 死因 | 発動 | 対象プール |
|---|---|---|
| `attacked` | する | 生存する人狼からランダム1名 |
| `lynched` | する | 生存者全員からランダム1名 |
| それ以外（`retaliation` 含む） | しない | — |

対象プールは猫又の死亡を確定させた後に評価する（自身が自然に除外される）。
YAML の形は `spec/DESIGN.md` §4.3。

## Why

### 死亡連鎖が構造的に止まる

無限ループを、検出機構ではなく**発火条件の限定**で解消する。

```
猫又A が死ぬ (attacked / lynched) → 道連れ → 誰かが死ぬ (retaliation)
                                            → retaliation では発動しない → 停止
```

猫又が複数いても連鎖しない。専用のループ防止コードが不要になる。

### 死因による分岐がゲームプレイ上の意味を持つ

襲撃されれば人狼が確実に1人減り、処刑されれば誰が死ぬか分からない。
同じ役職が死に方によって別の圧力を生む。

## エンジンへの要求

**Passive は「条件 → 効果」の組を複数持てる必要がある。**
死因ごとに対象プールが変わるため、`when` 1つ + `target` 1つでは書けない。
猫又固有の都合ではなく「Aの場合はX、Bの場合はY」という Passive は今後も出る。

## Consequences

`DeathCause` が Phase 1 で必須になる（D012）。
将来 `retaliation` で発動する役職を足す可能性があるため、
死亡連鎖の深さ上限を安全弁として持つ。
