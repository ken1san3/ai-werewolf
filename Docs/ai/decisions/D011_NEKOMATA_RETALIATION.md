# D011 猫又の道連れ仕様

## Status

Accepted (2026-08-29) — ユーザー決定
初版（襲撃死のみ）を改訂。処刑死でも発動するが、対象プールが異なる。

## Context

参照実装の猫又は
「人狼に襲撃された場合は人狼の中からランダムに一人を道連れ。
処刑された場合は生存者の中からランダムに一人を道連れ」。

本プロジェクトでもほぼ同等とするが、
**道連れによる死亡では発動しない**という制約を加える。

## Decision

猫又の道連れは、死因によって**発動可否と対象プールの両方**が変わる。

| 死因 (`DeathCause`) | 発動 | 対象プール |
|---|---|---|
| `attacked`（人狼の襲撃） | **する** | 生存する**人狼**からランダム1名 |
| `lynched`（昼の処刑） | **する** | **生存者全員**からランダム1名 |
| `retaliation`（道連れ） | しない | — |
| `cursed`（呪殺） | しない | — |
| `follow_death`（後追い） | しない | — |
| `sudden_death`（突然死） | しない | — |
| その他 | しない | — |

```yaml
id: nekomata
name: 猫又
team: village
count_as: village

passives:
  - type: retaliate_on_death
    rules:
      - when: { death_cause: attacked }
        target:
          selector: alive_by_tag
          tag: werewolf
          count: 1
          pick: random
        death_cause: retaliation

      - when: { death_cause: lynched }
        target:
          selector: alive_all
          count: 1
          pick: random
        death_cause: retaliation
```

### 適用順序

1. 猫又の死亡を確定させる
2. **その後**に対象プールを評価する（猫又自身は既に死亡しているため自然に除外される）
3. 対象を1名ランダムに選び、`death_cause: retaliation` で死亡させる
4. `retaliation` では道連れが発動しないため、ここで停止する

### 対象プールの補足

- `alive_all` は**その時点で生存している全プレイヤー**。
  死亡済みプレイヤーは含まない（選んでも効果が無く、
  道連れが空振りする実装依存の挙動になるため）。
  → `OPEN_QUESTIONS.md` Q17 で最終確認する。
- `alive_all` は陣営を問わない。人狼・妖狐・市民すべてが対象。
- 生存する人狼が0人の状態で猫又が襲撃されることは通常起きないが、
  対象プールが空の場合は**何も起きない**（例外にしない）。

## Why

### 発動条件を死因で絞ることで、死亡連鎖が構造的に止まる

`SPEC_REVIEW.md` H-12 で指摘した無限ループは、
ループ検出機構ではなく**発火条件の限定**で解消する。

```
猫又A 処刑 (lynched) → 道連れ → 猫又B 死亡 (retaliation)
                              → retaliation では発動しない → 停止
```

猫又が複数いても連鎖しない。専用のループ防止コードが不要。

### 死因による分岐がゲームプレイ上の意味を持つ

- 襲撃された場合は人狼が確実に1人減る → **人狼への抑止**
- 処刑された場合は誰が死ぬか分からない → **村側にとっての処刑リスク**

同じ役職が死に方によって別の圧力を生む。

## エンジンへの要求（初版から追加）

**Passive は「条件 → 効果」の組を複数持てる必要がある。**

初版の設計は `when` 句1つ + `target` 1つだったが、
猫又は死因ごとに対象プールが変わるため、
`rules: [{when, target}, ...]` というリスト構造が要る。

これは猫又固有の都合ではない。
「Aの場合はX、Bの場合はY」という Passive は今後も出るため、
最初からリストで受ける形にすること。
単一ルールは要素数1のリストとして扱う。

## Consequences

- `DeathCause` が Phase 1 で必須（`decisions/D009`）
- Passive のスキーマが `rules[]` になる
- 最終日に猫又を処刑し、道連れで最後の人狼が死んだ場合、
  `decisions/D005` の「全死亡処理の解決後に GAME_END_CHECK を1回」により
  両方の死亡を数えてから勝敗判定される。これで正しい
- 将来 `retaliation` で発動する役職を足す可能性があるため、
  **死亡連鎖の深さ上限は安全弁として持つ**（上限到達時は警告ログを出して打ち切る）
- 参照実装準拠モード（処刑時は生存者から、で同一）はほぼ本仕様と一致する。
  差分は `retaliation` で発動しない点のみ

## Verification

- 猫又が襲撃されて死亡したとき、生存する人狼の中から1人がランダムに死ぬ
- 猫又が処刑されたとき、生存者の中から1人がランダムに死ぬ
- 処刑時の道連れ対象に人狼・妖狐・市民のいずれもが選ばれうる
- 道連れ対象の抽選時点で、猫又自身が候補に含まれない
- 猫又が狩人に護衛されたとき、道連れが発動しない
- 猫又Aの道連れで猫又Bが死んだとき、猫又Bの道連れが発動しない
- 道連れで死んだプレイヤーの `DeathCause` が `retaliation` になる
- 最終日に猫又を処刑し、道連れで最後の人狼が死んだ場合、
  市民陣営の勝利になる（死亡をすべて解決してから判定される）
- 対象プールが空でも例外にならない
- 死因ごとに対象プールが違う Passive が、YAMLの `rules[]` だけで表現される
