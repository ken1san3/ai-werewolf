# D011 猫又の道連れは襲撃死のみで発動する

## Status

Accepted (2026-08-29) — ユーザー決定
「猫又は狼に襲撃された場合のみ。猫又自身が道連れで死亡しても発動しない」

## Context

参照実装の猫又は
「人狼に襲撃された場合は人狼の中からランダムに一人を道連れ。
処刑された場合は生存者の中からランダムに一人を道連れ」。

本プロジェクトでは**処刑時の道連れを採用しない**。

また `SPEC_REVIEW.md` H-12 で、道連れの連鎖による無限ループの危険を指摘していた。

## Decision

猫又の道連れは、`DeathCause` が `attacked`（人狼の襲撃による死亡）の場合**のみ**発動する。

```yaml
id: nekomata
name: 猫又
team: village
count_as: village

passives:
  - type: retaliate_on_death
    when:
      death_cause: attacked      # これ以外では発動しない
    target:
      selector: alive_by_tag
      tag: werewolf
      count: 1
      pick: random
    death_cause: retaliation
```

- 処刑death（`lynched`）では発動しない
- 道連れdeath（`retaliation`）では発動しない
- 呪殺・後追い等でも発動しない

## Why

### 1. 参照実装からの意図的な逸脱

処刑時の道連れは村側のリスクが大きく、
村人が猫又を処刑できない（＝処刑先が縛られる）状況を生む。
襲撃時のみに限定することで、猫又を
「**人狼への抑止**」という役割に絞る。

### 2. 死亡連鎖の問題が構造的に解消する

`SPEC_REVIEW.md` H-12 で指摘した無限ループは、
ループ検出機構を足すのではなく**発火条件を絞ることで消える**。

```
猫又A が襲撃される（attacked）→ 道連れ発動 → 人狼が死ぬ（retaliation）
                                          → retaliation では発動しない → 停止
```

猫又が2人いても、襲撃されるのは1人なので連鎖しない。
**特別なループ防止コードが不要になる。**

### 3. 発火条件がデータであることの検証になる

この変更は `passives[].when.death_cause` の値を変えるだけで実現される。
Python コードの変更を伴わないこと自体が、
`decisions/D009` の「役職追加は YAML だけで済む」要件のテストになる。

**参照実装準拠モード（処刑時も発動）を content として別途定義できること**を
実装の合格条件とする。

## Consequences

- `DeathCause` が Phase 1 で必須になる（`decisions/D009`）
- `retaliate_on_death` Passive の `when` 句は
  死因以外の条件（フェーズ、日数など）も将来受け付けられる形にする
- 汎用のループ防止は不要になるが、**将来 `retaliation` で発動する役職を
  足す可能性があるため、死亡連鎖の深さ上限は安全弁として持っておく**
  （上限到達時は警告ログを出し、その連鎖を打ち切る）

## Verification

- 猫又が襲撃されて死亡したとき、生存する人狼の中から1人がランダムに死ぬ
- 猫又が処刑されたとき、誰も道連れにならない
- 猫又が狩人に護衛されたとき、道連れが発動しない
- 猫又2人が同時に死ぬ状況でも連鎖が発生しない
- 道連れで死んだプレイヤーの `DeathCause` が `retaliation` になる
- 参照実装準拠（処刑時も発動）の猫又を、YAMLの変更だけで定義できる
- 生存する人狼が0人のときに猫又が襲撃されるケースが起きない、
  または起きても例外にならない
