# D009 初期実装役職を13種に確定する

Status: Accepted (2026-08-29) / ユーザー決定

## Context

参照実装は100種類以上の役職を持つが全部は実装しない。
「他の役職も次回以降実装できるような余裕を持たせる設計」が要件。

## Decision

市民 / 占い師 / 霊能者 / 狩人 / パン屋 / 猫又 / 人狼 / 強欲な人狼 / 賢狼 /
狂人 / 狂信者 / 囁く狂人 / 妖狐 の13種。
属性表と能力は `spec/DESIGN.md` §11。

**Phase 1 の完了判定はこの13役職が動くことで行う。**

### 拡張余地の担保

1. 役職は content の YAML 追加だけで足せること
2. 未実装の Effect / Passive を参照する定義は起動時にエラーにする（黙って無視しない）
3. Modifier の適用機構を Phase 1 で用意しておく（D008）
4. `medium_result` はタグ文字列。bool にしない
5. 役職IDと表示名を分離し、日本語名は content 側に置く

## Why

13役職は意図せずアーキテクチャの主要な軸をほぼ網羅している。

| 検証対象 | 役職の組 |
|---|---|
| 知識とチャット権限が陣営と独立 | 狂人 / 狂信者 / 囁く狂人（5軸が同一） |
| 同一属性で Ability だけが違う | 人狼 / 強欲な人狼 / 賢狼 |
| 第三陣営・カウント対象外・襲撃耐性 | 妖狐 |
| 死因による分岐 | 猫又 |
| 生存条件つきの定期公開通知 | パン屋 |

## エンジンへの新規要求

この13役職から、マスター仕様に無い機能要求が判明した。

1. 死因の区別（→ D012）
2. `uses.per_game`（強欲な人狼の「ゲーム中一度だけ」）
3. Ability のターゲット数が可変（`count: 2`）
4. RandomTarget（プールをフィルタで指定できること）
5. InspectRole（陣営ではなく役職そのものを返す）
6. 条件つきの定期公開通知（生存判定を発火条件に含める）
7. Passive が「条件 → 効果」を複数持つこと（→ D011）

## Consequences

標準9人村プリセットはこのうち6種を使う。残り7種は別プリセットで検証する。
