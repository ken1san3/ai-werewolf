# D010 賢狼は襲撃に成功した場合のみ役職を知る

## Status

Accepted (2026-08-29) — ユーザー決定
「賢狼は襲撃に成功した場合に知れるようにした方がいい。
これはどちらかというと死んだ人間の役職を乗っ取るというコンセプトのためのキャラ」

## Context

参照実装の説明文は「襲撃した人の役職を知ることができる」とのみ書かれており、
襲撃が護衛で防がれた場合・妖狐で失敗した場合の挙動が不明だった
（旧 `OPEN_QUESTIONS.md` Q14）。

Reviewer は「襲撃先に選んだ時点で知る」を推奨したが、**却下された。**

却下の理由は設計意図にある。賢狼の情報は偵察のためではなく、
**死んだプレイヤーの役職を騙る（乗っ取る）ため**にある。
死んでいない相手の役職を知っても、その役職を騙れば本人に否定されるため意味がない。

## Decision

賢狼は、**自陣営の襲撃が成立し対象が実際に死亡した場合にのみ**、
その対象の役職IDを知る。

| 状況 | 賢狼は知るか |
|---|---|
| 襲撃成功・対象死亡 | **知る** |
| 狩人に護衛され死ななかった | 知らない |
| 妖狐で襲撃が無効だった | 知らない |
| 対象が他の要因で先に死んでいた | 知らない |
| 強欲な人狼の2人襲撃で2人死亡 | **2人とも知る** |

### 解決順への含意

情報取得 Effect は、襲撃と死亡判定の**後**に置く。

```
30 Protect
40 Inspect          （占い）
50 Attack
70 DeathResolve     ← ここで死亡が確定
75 InspectDeadRole  ← 賢狼はここ
```

Reviewer が推奨した「選んだ時点で知る」案は、
InspectRole を Protect より手前へ置ける利点があったが、
ゲームデザイン上の意図と矛盾するため採用しない。

### 通知タイミング

賢狼への通知は **DeathResolve 直後**（道連れ等の連鎖death より前）に行う。

理由: 猫又を襲撃した場合、道連れで賢狼自身が死ぬ可能性がある。
通知を連鎖の後にすると「賢狼が死んだので情報を受け取れない」という
実装依存の挙動になる。**先に通知することで決定的にする。**

## Why

- 役職騙りという設計意図に沿う
- 「護衛されたかどうか」が賢狼の情報から間接的に漏れない
  （選択時点で知る案だと、狩人の護衛先が推測されうる）
- 情報の価値が「対象が確実に死んでいる」ことに結びつく

## Consequences

- Effect の解決順に `InspectDeadRole`（priority 75 相当）が追加される
- 賢狼は襲撃が失敗した夜には何も得ない。
  これは「襲撃失敗の事実」自体を賢狼へ伝えるかとは別問題
  （人狼陣営は朝の結果から襲撃失敗を知れるため、実質的に区別できる）
- 通知内容は役職**ID**。`decisions/D003` の `inspect_result`（陣営）ではない

## 将来の拡張余地

ユーザーの言う「乗っ取る」が、将来的に
**賢狼が対象の役職そのものを取得する**能力を意味する可能性がある。

その場合は Modifier（`decisions/D008`）ではなく
**Role Replacement**（D008 の Non-goals）に該当する。
現時点では実装しないが、`InspectDeadRole` の結果を
Role Replacement の入力として使える形にしておくこと。

## Verification

- 賢狼を含む人狼が襲撃に成功し、賢狼だけが対象の役職IDを受け取る
- 対象が狩人に護衛された場合、賢狼が何も受け取らない
- 妖狐を襲撃した場合、賢狼が何も受け取らない
- 強欲な人狼の2人襲撃で2人死亡した場合、賢狼が2件受け取る
- 猫又を襲撃して道連れで賢狼が死んだ場合でも、賢狼は情報を受け取っている
- 賢狼以外のプレイヤーがこの通知を受け取らない
