# D004 人狼ジャッジメントを参照実装とする

## Status

Accepted (2026-08-29) — ユーザー決定
「基本的には人狼ジャッジメントの仕様を参考にしてください」

## Context

マスター仕様はゲームルールの既定値をほとんど定義していない
（初日処刑、初日占い、投票同数、連続ガード、霊能通知タイミング等）。
実装者が個別に判断すると、後から全面的なやり直しになる。

## Decision

ルール・役職仕様・設定項目の判断基準を**人狼ジャッジメント（そらいろ株式会社）**に置く。

- 調査結果は `spec/JUDGMENT_REFERENCE.md` に集約する。
  **同じことを再調査してトークンを使わない。**
- 仕様に記述がない挙動で判断に迷った場合、まず JUDGMENT_REFERENCE を見る。
  そこにも無ければ `OPEN_QUESTIONS.md` へ起票し、ユーザーへ確認する。
- ただし**そのままコピーはしない**。人狼ジャッジメントは100種類以上の役職を持つが、
  本プロジェクトの Phase 1 スコープは標準9人村である。

## Why

- ゲームバランスと細部が実プレイで検証済み
- 役職属性のデータモデル（5軸）がそのまま設計の参考になる（`D003`）
- ユーザーがこのアプリのルールに習熟しているため、
  仕様の疑問を短時間で解決できる

## Consequences

- ルール設定項目が想定より多い。グローバル設定と役職固有オプションの
  2層構造が必須になる
- CO（カミングアウト）がシステム機能であることが判明。
  マスター仕様に存在しない概念のため、プロトコルへの追加が必要
  （`OPEN_QUESTIONS.md` Q9）
- 将来「人狼ジャッジメント互換モード」を content pack として持てる

## Non-goals

- 人狼ジャッジメントのUI・課金・ポイント・レーティングは対象外
- 100種類以上の役職を初期実装しない
