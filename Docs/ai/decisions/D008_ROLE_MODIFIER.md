# D008 Modifier を Role とは別概念にする

Status: Accepted (2026-08-29) / ユーザー提案
「狐憑きや恋人などの通常の役職を配られた後に追加される追加役職は別の概念にした方がいい」

## Context

参照実装には、通常の役職に重ねて付与されるものが複数ある。

| 例 | 付与 | 効果 |
|---|---|---|
| 狐憑き | 配役時 | 勝利条件が妖狐陣営へ / 占われると呪殺 / 後追い |
| 恋人 | 初夜（キューピット） | 勝利条件が恋人陣営へ / 相方の死亡で後追い / 互いを認識 |
| 手玉 | ゲーム中（悪女） | 悪女の死亡で後追い |
| 呪い | 毎夜（一晩限り） | その夜に占われると呪殺 |

Role として実装すると「占い師でありかつ恋人」が表現できず、
呪いのような一時的状態も置き場所がない。
狐憑きの全属性が「役職に準ずる」なのは、それが Role ではなくオーバーレイだからである。

## Decision

Modifier を第一級の概念として追加する。プレイヤーは Role を1つ、Modifier を0個以上持つ。
判定・勝敗・襲撃はすべて実効属性（Role + Modifiers）を経由する。
詳細は `spec/DESIGN.md` §4.4。

役職そのものが入れ替わる機構（変化系・怪盗の交換）は Role Replacement と呼び、
本Decisionの対象外とする。マスター仕様 §8.2 は
`SwapRole` / `CopyRole` / `ChangeTeam` を並列に並べているが、両者は別の機構である。

## Why

- 直交する状態を素直に表現できる
- 狐憑きの「役職に準ずる」が特殊ケースではなく Modifier の既定動作として説明できる
- 勝利条件の上書きが1箇所に集約される
- Modifier を content として追加でき、MOD拡張の幅が広がる

## Consequences

Phase 1 では**データモデルと適用機構だけ**を実装する。
具体的な Modifier（恋人・狐憑き）は Phase 8。
