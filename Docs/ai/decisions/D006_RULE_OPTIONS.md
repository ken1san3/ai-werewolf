# D006 ルールは全てオプション化する

Status: Accepted (2026-08-29) / ユーザー決定
「全部対応できるような柔軟性を持たせる」「両対応可能に」「全部オプションで変更可能に」

## Context

参照実装のルール設定はグローバル設定と役職固有ルールの2層で数十項目ある。
ユーザーの意向は、特定の既定値に決め打ちせず全ての選択肢に対応すること。

## Decision

ルールを2層の設定として持ち、プリセットとして配布する。
役職固有オプションは役職定義側に持たせ、ゲームコアはその意味を知らない。
分岐はコアに書かず、`restrictions` として宣言的に表現する。
設定項目の一覧は `spec/DESIGN.md` §5。

**プリセットの値は初期値であって仕様ではない。**
テストは既定値に依存せず、必要な設定を明示的に組み立てる。

## Why

- 参照実装が全項目を設定にしている以上、後から足すと分岐が散らばる
- ルールを設定にしておくと、AIの戦略比較実験で条件を変えられる

## Consequences

Phase 1 の投票実装は決選投票・処刑見送り・無効票・自己投票をすべて扱う必要がある。
`VoteResult` は「処刑あり / 処刑なし / 決選投票へ」の3値を返す。
設定スキーマのバリデーションが必要。テストの組み合わせが増える。
